# Artwork color pipeline

Use this skill before editing or exporting raster assets from `design/references/` or other designer-provided sources. The master is the source file; derived web images are replaceable outputs. Read [the project's color method](../../../docs/art-color-pipeline.md) and the relevant current `LESSONS.md` color/edge sections. Keep source files and user edits intact.

1. **Inventory and map.** Identify each source's dimensions, alpha, ICC profile, color mode, and hash. Distinguish the clean background from the composite text reference. Map exact crop boxes, overlaps, displayed widths, layer order, and destinations before exporting. If ICC is missing or the intended appearance is ambiguous, record that uncertainty instead of assigning a guessed profile. Do not confuse *Assign Profile* (changes interpretation) with *Convert to Profile* (changes RGB numbers to preserve appearance).
2. **Choose a delivery color space deliberately.** For this site's broad web baseline, convert a tagged source to sRGB with a color-managed transform, then embed the sRGB ICC in the output. Preserve an untouched original-format crop when a high-bandwidth or editorial fallback is needed; keep it outside `public/` until that selector is actually implemented, since dormant files still increase deployment size. A wide-gamut P3 variant requires a separately measured browser/device case. Never compensate a color complaint with a blanket channel adjustment such as `+6 red` without diagnosing source profile, transform, codec, browser, and display.
3. **Encode for measured quality and speed.** Export from the master or one color-managed intermediate, never from an earlier lossy image. Compare at least high-quality lossy and lossless candidates for color-sensitive art. Keep alpha exact; inspect partly transparent boundaries, hidden edge RGB, crop seams, red/orange regions, gradients, and fine graphics. Preserve/declare ICC explicitly: `cwebp` otherwise strips metadata by default. Use size and load priority appropriate to rendered dimensions; the visible hero must load eagerly, later sections can use lazy loading and a small color-managed preview.
4. **Verify the decoded result.** Compare candidate pixels against the *same color-managed* master, masking invisible pixels in color metrics. Include local-region and high-percentile errors so global averages cannot hide a small damaged mark. Check signed color drift and a perceptual color measure where useful. Escalate a failing region to less aggressive compression or lossless. Check ICC and alpha after decoding. Then capture actual WebKit screenshots on iPhone 17 Pro and Pro Max, inspect joins/full composition, and measure first-view and distant-scroll behavior if delivery changes. A small file alone is not a pass.
5. **Record the decision.** Save source hashes, profile/transform, crop boxes, encoder options, candidate sizes, measured errors, browser evidence, and performance evidence. Update the required CHANGELOG entry and affected project docs. Report what remains unmeasured (for example P3 displays, field LCP, or exact Photoshop ACE parity). Do not claim visually lossless or identical color on all displays without evidence.

For the current long background, `tools/convert-art-webp.py` builds the active sRGB WebP tiles and `tools/slice-background-png.py` builds source-exact Adobe RGB reserve PNGs. Adapt these tools only after checking the current source and crop map; do not assume every new image has the same ICC, dimensions, or optimal codec settings.
