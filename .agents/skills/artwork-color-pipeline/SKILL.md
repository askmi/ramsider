# Artwork color pipeline

Use this skill before transforming raster assets or changing their displayed geometry. Keep source files and user edits intact. For CSS-only image geometry, use the geometry contract below without re-encoding assets or rerunning unrelated color/export checks. For source, codec or delivery changes, also follow the color workflow and read [the project's color method](../../../docs/art-color-pipeline.md). Retrieve relevant `LESSONS.md` image width, aspect, color and edge failures before similar work.

## Geometry contract before implementation

1. **Separate the requirements.** Measure the source dimensions and actual browser content viewport/cutout. Define independent checks for frame width, photo width, undistorted photo ratio, required content visibility and fixed controls. A full-width frame or matching source hash cannot prove a full-width photograph. Browser chrome changes available height at the same width.
2. **Resolve unequal aspect ratios.** For width `W` and source `Sw×Sh`, proportional photo height is `W×Sh/Sw`. Compare it with available height before selecting a fit. When full width, no distortion and all source content are required, use proportional width with accessible vertical overflow or an approved responsive recomposition. `contain` can leave side bands; `cover` can crop captions/diagrams. Neither satisfies all those requirements automatically. Never stretch image axes independently (`object-fit:fill`, separate width/height scales) to force a fit. Do not silently crop meaningful regions. If simultaneous full visibility without scrolling is also required, assess source layers for recomposition and make unresolved requirements explicit.
3. **Keep layers aligned.** Scale photo and source-positioned live text/callouts as one proportional plane. A viewport-filling metal frame needs separately adaptable borders (for example nine-slice), preserving corners and thickness. Inspect sprite ratios too. CSS overflow and object-fit must describe the actual image element, not just its wrapper.
4. **Verify the real output.** Assert photo width equals its intended inner width within 1 CSS px and its proportional height differs from `renderedWidth×Sh/Sw` by no more than 1 CSS px (or document a justified browser rounding tolerance). Inspect ready screenshots on Pro and Max, at multiple heights of the same phone width and representative wide/landscape sizes, for every distinct source composition. Check full bottom-content access, overlay alignment, side bands, clipped labels and fixed controls. Source-byte/color checks are additional evidence, never geometry approval. Reuse `tests/e2e/technology-width.spec.ts` for this viewer; adapt checks to the current feature instead of copying its source ratio or gesture policy globally.
5. **Recheck affected interactions.** If overflow changes, verify native vertical pan, keyboard/wheel, bounded reversible horizontal navigation and Arabic RTL as applicable; scrolling must not also change groups. In a protected media view, pending/error freezes its scroll/navigation, the old complete frame stays visible, and decoded replacement resets position only on commit. Keep Close/Retry usable. Distinguish emulated content tests from physical Safari/Telegram chrome and synthetic events from native input.

Record the chosen geometry and actual evidence in the existing topic document and CHANGELOG. Reuse existing sections for diagnosis, plan and results; create a separate document only for a genuinely distinct maintained topic or an explicit user request. After superseding a policy, reread the complete affected narrative and reconcile its callers, not only headings/tables. Instruction changes and passing UI tests do not guarantee future agent behavior; record controlled eval status separately.

## Color and raster delivery workflow

The master is the source file; derived web images are replaceable outputs.

1. **Inventory and map.** Identify each source's dimensions, alpha, ICC profile, color mode, and hash. Distinguish the clean background from the composite text reference. Map exact crop boxes, overlaps, displayed widths, layer order, and destinations before exporting. If ICC is missing or the intended appearance is ambiguous, record that uncertainty instead of assigning a guessed profile. Do not confuse *Assign Profile* (changes interpretation) with *Convert to Profile* (changes RGB numbers to preserve appearance).
2. **Choose a delivery color space deliberately.** For this site's broad web baseline, convert a tagged source to sRGB with a color-managed transform, then embed the sRGB ICC in the output. Preserve an untouched original-format crop when a high-bandwidth or editorial fallback is needed; keep it outside `public/` until that selector is actually implemented, since dormant files still increase deployment size. A wide-gamut P3 variant requires a separately measured browser/device case. Never compensate a color complaint with a blanket channel adjustment such as `+6 red` without diagnosing source profile, transform, codec, browser, and display.
3. **Encode for measured quality and speed.** Export from the master or one color-managed intermediate, never from an earlier lossy image. Compare at least high-quality lossy and lossless candidates for color-sensitive art. Keep alpha exact; inspect partly transparent boundaries, hidden edge RGB, crop seams, red/orange regions, gradients, and fine graphics. Preserve/declare ICC explicitly: `cwebp` otherwise strips metadata by default. Use size and load priority appropriate to rendered dimensions; the visible hero must load eagerly, later sections can use lazy loading and a small color-managed preview.
4. **Verify the decoded result.** Compare candidate pixels against the *same color-managed* master, masking invisible pixels in color metrics. Include local-region and high-percentile errors so global averages cannot hide a small damaged mark. Check signed color drift and a perceptual color measure where useful. Escalate a failing region to less aggressive compression or lossless. Check ICC and alpha after decoding. Then capture actual WebKit screenshots on iPhone 17 Pro and Pro Max, inspect joins/full composition, and measure first-view and distant-scroll behavior if delivery changes. A small file alone is not a pass.
5. **Record the decision.** Save source hashes, profile/transform, crop boxes, encoder options, candidate sizes, measured errors, browser evidence, and performance evidence. Update the required CHANGELOG entry and affected project docs. Report what remains unmeasured (for example P3 displays, field LCP, or exact Photoshop ACE parity). Do not claim visually lossless or identical color on all displays without evidence.

For the current long background, `tools/convert-art-webp.py` builds the active sRGB WebP tiles and `tools/slice-background-png.py` builds source-exact Adobe RGB reserve PNGs. Adapt these tools only after checking the current source and crop map; do not assume every new image has the same ICC, dimensions, or optimal codec settings.
