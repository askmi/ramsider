Средняя и номинальная частота кадров совпадают; это проверка метаданных, не исчерпывающая проверка постоянства длительности каждого кадра. Новые исходники укладываются в проверенные входные ограничения существующего кодировщика; окончательная проверка выходов всё равно обязательна.

AAC — уже сжатая звуковая дорожка. Текущий процесс умеет копировать её без повторного сжатия. В новых записях звук около125,5–126,6 кбит/с по метаданным; политика сохранять его неизменным остаётся той же. Для доказательства сравниваются сами звуковые пакеты, не только заявленный битрейт.

**Обнаруженная особенность входов:** тег языка аудио у всех четырёх файлов — `eng`, включая три новые версии. Не используем его как доказательство языка речи или как ключ выбора. Задаём `ru`, `de`, `es` явно по предоставленным версиям; кодировщик уже записывает выходные теги `rus`, `deu`, `spa`. Сам мастер менять не нужно.

У трёх новых исходников последовательности сжатых видеопакетов полностью совпадают друг с другом, а аудиопакеты различаются. Их видеопоток отличается от английского исходника. Это подтверждено пакетными отпечатками, а не только одинаковой длительностью. **Готовый английский HLS нельзя просто назначить новым языкам:** он содержит английский звук. Текущий безопасный механизм `--reuse-package` требует идентичного полного исходника и его звука, поэтому межъязыковое переиспользование через этот флаг не разрешено. Для первого выполнения используем существующий самостоятельный процесс для каждого языка. Оптимизация «один раз закодировать общую картинку, отдельно собрать с тремя звуками» потребовала бы отдельной доработки и проверок; в этот план она не входит.

## Порядок выполнения — тот же, что у английского ролика

### 1. Зафиксировать входы

Использовать оригиналы из `design/video/1`, привязать каждую операцию к полному SHA из инвентаризации. Названия языков задавать явно. Оригиналы остаются нетронутыми и локальными; пути перенесённого английского мастера обновлять в новых инструкциях/командах, не переписывая исторические доказательства.

Новые неизменяемые версии: `ru-v1`, `de-v1`, `es-v2` (ESv1 отклонён по бюджету аварийного качества) для того же ID `uno-introduction`. До запуска убедиться, что каталоги и архивы не существуют. Если версия уже опубликована, использовать новую версию, а не перезаписывать URL.

### 2. Перекодировать изображение и сформировать2-секундные фрагменты

Использовать [наш навык](../.agents/skills/mobile-hls-video/SKILL.md) и его [спецификацию](../.agents/skills/mobile-hls-video/references/specification.md), существующий FFmpeg9.0.2/libx264, preset `slow`,6потоков, выровненные закрытые группы50кадров при25кадрах/с. Сохранять соотношение сторон, частоту кадров, BT.709 limited и формат yuv420p.

| Качество изображения | Разрешение | CRF — параметр качества кодирования | Ограничение битрейта только изображения |
| --- | --- | ---: | ---: |
| Аварийное144p | 256×144 | 30 | 28кбит/с |
| Стартовое360p | 640×360 | 19 | 550кбит/с |
| 720p | 1280×720 | 18 | 2000кбит/с |
| 1080p | 1920×1080 | 18 | 4500кбит/с |
| 1440p | 2560×1440 | 18 | 8000кбит/с |
| 2160p | 3840×2160 | 17 | 14000кбит/с |

Это действующие настройки английской схемы, а не обещание одинакового размера или воспринимаемого качества для любого исходника. Сначала кодируется изображение с подходящими ключевыми кадрами, и одновременно FFmpeg формирует HLS-фрагменты. Простое разрезание исходного46Мбит/с MP4 на куски не решит проблему трафика.

**Звук каждого исходника — `-c:a copy` во всех6качествах и fallback.** Не понижать его на144p, не использовать английский звук для локализованного пакета. Изображение сжимается с потерями, звук дополнительно не перекодируется.

Ожидаемый результат при той же длительности: для каждого качества30фрагментов по2с + короткий хвост около0,04с, init и плейлист. Точное количество/длительность подтвердит валидатор; нельзя молча убрать короткий хвост.

### 3. Собрать полный пакет

Для каждого языка текущий `encode.py` создаёт:

- `master.m3u8` — список доступных качеств с реально измеренным битрейтом, кодеками, разрешением и частотой кадров;
- по одному `index.m3u8`, `init.mp4` и набору `.m4s` для каждого качества; звук находится вместе с изображением в каждом фрагменте;
- `fallback.mp4` из720p, без нового сжатия звука/изображения при сборке, с метаданными в начале для последовательного просмотра;
- отчёт с настройками, SHA входа/выходов, длительностями, отпечатком исходных аудиопакетов и контрольными суммами;
- отдельный архив `design/derived/product-films/uno-introduction-<locale>-v1.tar` для каждого нового языка.

При английской структуре это ожидаемо200файлов на язык,600новых,800на4активных языка. Это рабочая оценка структуры, не уже созданные файлы. Плеер получает отдельные медиафайлы через HTTP; архив используется при сборке сайта и не скачивается зрителем.

### 4. Проверить пакеты до включения

Для каждого языка выполнить `validate.py --source <его оригинал>` с соответствующим encoding receipt, пакетом и архивом. Проверить полный граф master→playlist→init/segments, все SHA/размеры, закрытые ссылки, реальные codecs/fps/разрешения/bitrate, начало каждого фрагмента с независимо декодируемого кадра, совпадение временных границ качеств, звук/изображение и полное декодирование.

Сравнить последовательность **всех аудиопакетов каждого качества и fallback именно с оригиналом этого языка**. Подготовить таблицу фактических средних/максимальных размеров одного2-секундного фрагмента и полного60,04-секундного ролика для всех6качеств каждого языка. Не переносить размеры английского как измерения новых записей.

Бюджет аварийного уровня — цель≤192кбит/с **вместе со звуком и контейнером**. Его нужно измерить отдельно для3новых озвучек. При превышении экономим на изображении и повторяем проверки; звук не ухудшаем. Бюджет не заменяет проверку качества и не является уже доказанным результатом.

Проверить реальные декодированные кадры (движение, лицо, детали, логотип, градиенты), сопоставить с собственным исходником. Беззвучные автоматические проверки не подтверждают субъективное звучание или настоящий язык речи; при необходимости независимая проверка речи делается в среде, не мешающей владельцу. Не блокировать подготовку из-за неподтверждённого filename-language вывода: владелец уже назвал языки, а теги `eng` требуют явного задания выходной метки.

### 5. Зарегистрировать3добавочных языка

Подготовить11переведённых подписей фактической озвучки для каждого языка. Вызвать `register.py` с точным PASS validation receipt и новым архивом/каталогом; сохранить `en-v3` активным. Получится4активных записи с различными `audioLocale`, а не4активные версии одного и того же языка.

Архивы хранить через существующий Git LFS, подготовленные публичные файлы извлекать существующим Node-скриптом во время сборки. Не добавлять1,39ГБ оригиналов в Git и не запускать перекодирование в Vercel. Все объекты нового пакета должны войти в одну проверенную публикацию до использования его URL. Новые URL неизменяемы.

### 6. Проверить локали, предзагрузку и воспроизведение

Добавить явную проверку всех11локалей по таблице выше: `audioLocale`, подпись, manifest, fallback,6правильных стартовых URL. Для3новых языков — реальный запуск/продолжение/перемотка/закрытие и повторное открытие на native WebKit и MSE. Английская регрессия остаётся обязательной.

Предзагрузка остаётся **3×2с только выбранной версии**, после hero/fonts/отрисовки, без ожидания со стороны страницы и без autoplay. Проверить отсутствие четвёртого стартового сегмента до намерения, фактическое потребление кэша, корректные Range, отсутствие английского URL на `ru/de/es`, восстановление после отказа CacheStorage/сети и отмену при смене локали. Измерить план≤1MiB; если он не помещается, не ослаблять ограничение молча. На неподдерживаемом/неудачном пути фоновая загрузка уже должна отказывать без блокировки Play.

Кэш `film-start-v1` сейчас удаляет объекты вне выбранного набора. Проверить последовательный переход `ru→de→es→fr`, возврат через историю/BFCache и вкладки с разными локалями: допускается обычная сеть при вытеснении, но не подмена озвучки и не блокировка. Полное сохранение4роликов для offline не является целью.

Проверить холодный/прогретый старт, полное воспроизведение при слабой и восстанавливающейся связи, падение/рост качества, ошибки/Retry, паузу/перемотку, освобождение звука/запросов и отсутствие новых ошибок. Native iPhone сам управляет адаптацией; hls.js-настройки его не контролируют. Успех на одной быстрой сети не доказывает отсутствие лагов.

**Все локальные браузерные тесты — muted=true и volume=0 до Play**, через [silent-media.ts](../tests/e2e/silent-media.ts). Старый `tools/measure-product-film.mjs` пока не использовать без исправления CHG0148: у него отсутствует отключение звука. Субъективное прослушивание и физические устройства отражать отдельно, не выдавая эмуляцию за доказательство реального iPhone.

### 7. Проверить сборку и подготовить показ

Проверить чистую сборку из Git/LFS без частных мастеров и FFmpeg, целостность всех4пакетов, размер стартовых данных, фактическое отсутствие загрузки всех языков сразу. Выполнить проверку типов, lint, применимые тесты и native `/review` фактического diff реализации. Проверить реальные Pro402×874/Max440×956 DPR3, Arabic RTL, native controls/fullscreen/ландшафт и актуальные языковые подписи. Отдельно измерить влияние на загрузку страницы; увеличение пакетов хранения не должно означать увеличение начального трафика в4раза.

Результаты фиксировать по каждому языку отдельно. После предусмотренной задачи внедрения и разрешённой публикации проверить exactSHA/deploy, реальные публичные файлы/MIME/cache/Range, запуск всех4языков и английский fallback. **Последующим сообщением владелец явно разрешил выполнение и публикацию в main; эта авторизация действует для текущего внедрения.**

## Ориентир по объёму, не результаты конвертации

Готовый английский архив всех6качеств и fallback: **222965760байт ≈223MB**. Если использовать его как грубый ориентир на язык,3новых пакета добавят около**669MB**, вместе с английским получится около**892MB** подготовленных архивов. Реальные значения зависят от закодированной картинки и будут получены после конвертации; это не верхняя граница и не расход трафика одного просмотра. Отдельно все4частных оригинала сейчас занимают **1392338277байт ≈1,392GB** и остаются локальными.

Английская предзагрузка первых6с с тремя метаданными сейчас **440431байт**. Новые языки должны получить свои измеренные значения, а не это число по умолчанию. На странице загружаются только данные выбранного языка; остальные версии хранятся для других локалей и увеличивают общий размер подготовленного деплоя/сборки. Проверить актуальную доступную ёмкость Git LFS и артефакта сборки перед публикацией; не обещать неизвестную стоимость или достаточность тарифа.
