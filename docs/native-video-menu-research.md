# Исследование заливки штатного меню видео

Дата: 2026-10-27. CHG0151 REOPENED. Область: исследование и варианты, без изменения плеера. Решение об интерфейсе принимает заказчик.

## Точный запрос и прежняя ошибка

На втором скриншоте заказчика — штатное меню Chromium по нижним правым трём точкам, с пунктом Picture in Picture. Нужно изменить его заливку на полупрозрачную, скруглить углы, сохранить расположение и доступность настроек при разворачивании видео. Отдельный блок Playback Options под видео не соответствует этому запросу. Ранее агент изменил ожидаемый результат без объяснения ограничения; старые технические approvals не являются приёмкой этого UX.

## Что в текущем решении своё, а что браузерное

«Свой плеер» ранее было неточным названием. У нас своя интеграция: каталог языков, модальное окно, ограниченная предварительная загрузка, адаптер выбора качества и обработка ошибок. Native HLS на iPhone / библиотека hls.js на MSE-пути выполняют потоковое воспроизведение. Браузерный HTML-элемент video декодирует и выводит медиа, а его атрибут controls включает также штатную панель с трёмя точками. Отдельное меню FilmOptions — наш код, но оно не заменяет штатное меню. Именно это разделение было объяснено пользователю после его вопроса 2026-10-27.

Владение оформлением controls и использование браузера для декодирования — разные решения. Собственные или готовые UI-компоненты позволяют управлять оформлением без написания своего видеодекодера или повторной нарезки HLS. Источники реализации: components/ProductFilm.tsx, components/FilmOptions.tsx, lib/film-playback.ts.

## Что можно изменить без замены управления

В исследованной версии Chromium у меню есть два встроенных цвета: светлый и тёмный. Строка `video { color-scheme: dark; }` выбирает тёмную тему. Исходный код Chromium задаёт непрозрачные `#fff` / `#3b3b3b` и радиус 2px. Это изменение темы, а не произвольной заливки или прозрачности. [Исходный CSS Chromium](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/media_controls/resources/mediaControls.css).

Требуемый элемент имеет внутреннее имя `-internal-media-controls-overflow-menu-list`. Парсер Chromium разрешает внутренние псевдоэлементы только в браузерной таблице стилей. Внешний CSS сайта не получает такой доступ. Отдельный доступный `::-webkit-media-controls-panel` относится к панели управления, а не к этому popup. [Парсер Chromium](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/css/css_selector.cc), [создание меню](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/media_controls/elements/media_control_overflow_menu_list_element.cc).

Shadow DOM — внутренняя структура элемента. У браузерного видео сайт не получает эту структуру через `video.shadowRoot`. Инспектор разработчика может смотреть глубже; это не доступная посетителю возможность JavaScript сайта. [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_shadow_DOM).

## Практический эксперимент

Изолированная страница с тем же подготовленным английским MP4 и штатными controls. Playwright Chromium **153.0.8010.12**, 960×680, без воспроизведения: `muted=true`, `volume=0`, `paused=true`, счётчик событий Play=0. Chromium также запущен с `--mute-audio`. Видео и HTML получены локально через тестовую маршрутизацию; сайт, сервер и медиапакеты не изменялись.

Через обычные стили страницы проверены:

| Попытка | Результат точного popup |
| --- | --- |
| Светлая тема | `rgb(255,255,255)`, opacity 1, радиус 2px |
| `color-scheme: dark` | `rgb(59,59,59)`, opacity 1, радиус 2px |
| Внутренний / предполагаемый webkit popup selector, `!important`, прозрачный background, 20px radius | Не применились: остались белый, opacity 1, 2px |
| `::part(overflow-menu-list)` | Синтаксис поддержан, но popup не экспортирует такой part; изменения не применились |
| Стили доступной панели `::-webkit-media-controls-panel` | Не изменили заливку popup |
| Тёмная тема + настоящий fullscreen элемента VIDEO | Тёмный popup остался непрозрачным |

Внутренний узел прочитан через диагностический Chrome DevTools Protocol. Это привилегированное чтение для доказательства, а не предлагаемый способ работы сайта. Для `::-internal-…` и предполагаемого `::-webkit-media-controls-overflow-menu-list` CSS.supports(selector(...)) вернул false. Скриншоты светлого/тёмного/попытки прозрачности просмотрены: исходное непрозрачное меню соответствует типу меню заказчика; прозрачности нет.

Повторяемый источник эксперимента, версия, значения, ограничения и SHA изображений: [receipt](evidence/video/native-menu-css-research.json). Снимки: `screenshots/video/native-menu-research/`. Не проверялись физические телефоны и все версии браузеров; результат относится к указанному Chromium. Нет утверждения о видеокачестве/звуке по этому эксперименту.

## Варианты для решения заказчика

| Вариант | Что сохраняется / меняется | Прозрачность и углы | Объём / ограничения |
| --- | --- | --- | --- |
| Штатное меню + тёмная тема | Те же controls и трёхточечное меню | Тёмный фон; произвольная прозрачность и 20px углы не получены | Минимальный CSS. Частичный компромисс, исходный результат не выполнен |
| CSS/JS обходы внутренних элементов | Попытка сохранить штатное управление | Надёжного рабочего способа для этого popup не найдено; конкретные селекторы отклонены | Инспектор/расширение не являются решением для посетителей сайта. Гибридная накладка поверх native controls не доказана, особенно в native fullscreen |
| Готовые компоненты управления, например Media Chrome | Панель рисуется компонентами сайта поверх того же video; трём точкам можно сохранить место и вид | Документированы фон/радиус меню, можно задать rgba и скругление | Предпочтительный кандидат для согласования. Меняется интерфейс управления, а не только CSS штатного popup. Понадобятся привязки наших quality/Auto, локалей, жизненного цикла и отдельная проверка fullscreen |
| Свои controls | Полный контроль над панелью и точным видом | Да, через обычный CSS | Больше собственного кода, поддержки и проверок play/seek/mute/keyboard/PiP/fullscreen. Это тоже согласуемая замена интерфейса |

Media Chrome предоставляет отдельные UI-компоненты, заменяемые иконки и настраиваемое меню; это не браузер Chromium, несмотря на название. Для меню есть `--media-settings-menu-background`, `--media-menu-background`, `--media-menu-border-radius`. Возможность этих настроек документирована; интеграция в Ramsider ещё не выполнена и не сертифицирована. [Меню](https://www.media-chrome.org/docs/en/components/media-settings-menu), [стилизация](https://www.media-chrome.org/docs/en/styling).

Официальный репозиторий Media Chrome также сообщает об объединении команд и предлагает Video.js для новых проектов, хотя сам Media Chrome не помечен там deprecated. Поэтому Media Chrome здесь — кандидат на минимальную UI-интеграцию с нашим существующим движком, а не заранее выбранная зависимость. При выборе готовой оболочки нужно сопоставить этот путь с актуальным Video.js 10 на небольшом прототипе. [Статус Media Chrome](https://github.com/muxinc/media-chrome).

Как архитектурный вариант, существующие подготовленные HLS-файлы, native HLS и hls.js можно сохранить, привязав UI к имеющимся методам. Это вывод из разделения текущего адаптера `lib/film-playback.ts` и управления; автоматическая совместимость не доказана. Нельзя ожидать, что библиотека сама обнаружит наши ручные native-HLS варианты. Размер добавленного JavaScript и поведение измеряются на прототипе после выбора; оценки байтов и сроков сейчас не выдумываются.

У Plyr тоже есть CSS-настройки меню, однако официальный репозиторий теперь объявляет проект deprecated с обновлениями безопасности и рекомендует Video.js 10 для новых работ. Поэтому старые рекомендации «просто поставим Plyr» нельзя переносить автоматически. [Официальный статус Plyr](https://github.com/sampotts/plyr).

## Отдельное критическое ограничение iPhone

Полноэкранный режим контейнера страницы (видео + HTML-меню) и системный полноэкранный видеоплеер iPhone — разные механизмы. Там, где доступен Element Fullscreen API, разворачивается общий контейнер. В системном iPhone-плеере сайт не может оставить поверх него произвольное HTML-меню. Вариант с заполнением видимой области страницы сохраняет наше меню, но не гарантирует скрытия браузерной панели. Это нужно выбрать до внедрения, а не подменять один режим другим молча. Физическая проверка остаётся обязательной для соответствующих обещаний.

[Fullscreen API](https://fullscreen.spec.whatwg.org/), [открытый вопрос поддержки произвольных элементов на iPhone в WebKit](https://bugs.webkit.org/show_bug.cgi?id=206854), [документированное различие native/full-window в Plyr](https://github.com/sampotts/plyr/blob/master/README.md).

## Рекомендация и граница текущего результата

Если нужно только убрать белую заливку самым простым способом — согласовать тёмную native-тему, честно оставив её непрозрачной. Если обязательны прозрачность, скругление и все наши настройки в одном меню, согласовать готовую управляемую UI-оболочку поверх видео, с нижними правыми тремя точками. Исследование поддерживает эту архитектурную рекомендацию, но не заменяет её прототипирование/QA.

Ни один из вариантов не внедрён, библиотека не установлена, видео не перекодировались, публикации нет. Сам дефект CHG0151 открыт. Исследование и исправление процесса рассматриваются отдельно от будущего исправления плеера.


## Selected implementation —2026-10-27
After this research and the iPhone shared/full-window tradeoff were explained, the owner chose ready-made control components and requested a gear icon. The corrected implementation uses MediaChrome4.19.4 as a lazy UI layer around the existing same video/streaming engine. The gear and translucent rounded settings remain inside the shared video presentation; the former below-video component is deleted. Current architecture, recovery/keyboard/platform behavior and limitations are in `docs/product-film.md`; current source-bound verification is `docs/evidence/video/ready-controls-verification.json`. Research experiments above remain historical native-menu CSS evidence, not a claim that browser-private controls became author-stylable.
