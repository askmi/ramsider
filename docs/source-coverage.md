## Independent findings and changes from this audit

1. **Product description was too thin.** The former `PRODUCT.md` named a premium electronic hookah but missed Fograiser positioning, personal vs hospitality audiences, user decisions, narrative order, repeated CTA roles, and factual dependencies. The revised [PRODUCT.md](../PRODUCT.md) and [reference-map.md](reference-map.md) now distinguish visible design content from verified product/commerce data.
2. **Gate numbering conflicted.** `AGENTS.md` had six gates; `discipline.md` had stages 0–7, while `PERFORMANCE.md` cited stage 6. They now share six stages, with review and production optimization in gate 5. This removes a routing ambiguity that could make a model skip or repeat work.
3. **Pixel comparison lacked calibration.** A 941 px export cannot be compared directly with the 402 CSS-px iPhone 17 Pro or 440 CSS-px Pro Max browser screenshot. [visual-qa.md](visual-qa.md) now requires a measured source-to-browser transform and matching crop before a numerical diff counts.
4. **The language of “100% automation” needed a testable boundary.** Instructions can require the model to execute every feasible check, capture evidence, and repair defects without asking the user to QA. They cannot prove a site with no app, destinations, or product records works. [definition-of-done.md](definition-of-done.md) must therefore be applied to implemented slices and state blocked external dependencies honestly.
5. **Redundant scaffolding would slow the model.** The detailed source discusses many optional services, agents, breakpoints, animation libraries, and new React APIs. They remain conditional in [TOOLS.md](../TOOLS.md) and [ARCHITECTURE.md](../ARCHITECTURE.md); the mandatory path stays reference inspection → implementation → browser visual/interaction evidence → code/performance review → recheck. An extra tool is justified only by a verification gap.
6. **The primary device was underspecified.** Earlier context said “modern iPhone Pro sized” and Playwright used 390 × 844. The user's current instruction sets iPhone 17 Pro as the base and Pro Max as the second required target; [mobile.md](mobile.md), [AGENTS.md](../AGENTS.md), and `playwright.config.mjs` now use 402 × 874 and 440 × 956 at DPR 3. Other devices are responsive adaptations.
7. **Installed skills needed routing.** [TOOLS.md](../TOOLS.md) now classifies the 9 remaining project-local skills. The pixel-perfect and Playwright workflows are core; the two broad design-generation skills and the unrelated build-tool skill were removed at the user's request. `playwright-interactive` is unavailable without its prerequisites.
8. **Repeated verification is deliberate.** The inspect → implement → browser screenshot → compare → fix → recheck sequence stays prominent in [AGENTS.md](../AGENTS.md), [discipline.md](discipline.md), and [definition-of-done.md](definition-of-done.md): entry rule, execution gate, and final audit. The latest user instruction explicitly favors this repetition. Other detail remains stage-indexed.
9. **Slice-level success could be mistaken for delivery.** The main rule and stage gate now require the entire requested scope to be integrated and checked as a long page after local section passes. [visual-qa.md](visual-qa.md) now defines what a material visual mismatch is without a false 0% pixel threshold.
10. **Tool availability could be mistaken for an executed test.** Playwright is installed and configured, but there is no rebuilt app or E2E suite. [TOOLS.md](../TOOLS.md), [discipline.md](discipline.md), and [definition-of-done.md](definition-of-done.md) now explicitly reject a zero-test runner as QA evidence and require repeatable browser checks when the app exists.
11. **A conditional review skill could interrupt autonomy.** The local `web-design-guidelines` skill used to ask the user for file paths when none were specified. It now discovers affected UI files itself and reports missing guidelines as an optional audit limitation while the core visual and behavior checks continue.
12. **Unverified claims could halt the local visual rebuild.** [PRODUCT.md](../PRODUCT.md), [AGENTS.md](../AGENTS.md), and [discipline.md](discipline.md) now distinguish faithfully reproducing source copy for local visual QA from confirming prices, certificates, health language, and destinations before publication or functioning commerce. No missing business data is fabricated.
13. **A lessons file alone is not project memory.** [LESSONS.md](../LESSONS.md) retains root-cause prevention rules, while [MEMORY.md](../MEMORY.md) now carries the current verified handoff across chats. [AGENTS.md](../AGENTS.md) requires retrieval at the start of substantive work and updates after material discoveries or corrections; the detailed trigger and stale-entry discipline live in [discipline.md](discipline.md). This is repository-file memory, not a claim that model weights or an SDK memory service were changed.
14. **Hooks were evaluated as a context optimization.** No project hook is installed: session/prompt hooks would add context, and there is no rebuilt app or passing test suite for a meaningful deterministic stop check. [CONTEXT_INDEX.md](../CONTEXT_INDEX.md) sets a staged loading budget; [AGENTS.md](../AGENTS.md) loads the implementer and testing skills at their separate stages. [TOOLS.md](../TOOLS.md) records the narrow criterion for a future hook.
15. **Instruction quality lacked a behavioral regression check.** Static document coverage cannot show whether a future model actually loads the right skill, views screenshots, repairs visual differences, or avoids unnecessary work on a typo. [agent-evals.md](agent-evals.md) now defines positive and negative task scenarios with trace/artifact evidence. No agent-run baseline has passed yet; a runnable site is still absent.
16. **A performance skill had an overbroad trigger.** The local Vercel React skill previously invited use for almost any component or page edit. Its description now targets data fetching, hydration, bundles, and measured rendering work, while retaining the underlying rules for relevant reviews. This reduces irrelevant skill loading without weakening the mandatory performance gate.

## Remaining dependencies, not hidden assumptions

The repository has no rebuilt site, production endpoint, confirmed copy/translation set, film, document PDFs, commerce/configuration backend, FAQ answers, or verified pricing/certification records. The render alone cannot resolve those. A future implementation should complete all independent work first, then surface only the decisions that genuinely block a functioning action or factual publication. Tool installation and a written gate are preparation; neither is evidence that the future site passed the gate.
