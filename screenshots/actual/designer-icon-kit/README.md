The customer rejected the uniform 28-source-px lift documented below. The **current** positions are in `docs/elements-mapping.md`: feature icons I09–I12 return to their original source Y, while seven visible technology icons I01–I05, I07–I08 use individual lifts of 21, 25, 19, 17, 15, 20 and 24 source px respectively. The three largest downward corrections from the rejected version are Light & Sound, Water Sensor and Touch & App. Icon PNG bytes, X, native sizes, connectors, dividers and labels are unchanged.

Current real WebKit DPR3 screenshots: `correction-feature-pro-en.png`, `correction-feature-pro-max-en.png`, `correction-feature-pro-ar.png`, `correction-technology-pro-en.png`, `correction-technology-pro-max-en.png`, `correction-technology-pro-ar.png`. The browser run waited for fonts and decoded images. `correction-geometry.json` contains 22 locale/device states: all icon-to-label gaps are positive (Pro 0.4–9.4 CSS px, Pro Max 0.5–10.3 CSS px), every document fits its 402/440 CSS-px viewport, and the viewport meta is correct. The four restored feature positions deliberately have the small original reference gaps. Focused icon Playwright suite: 8/8 pass after the final production build; full suite: 78 pass / 18 expected skip. Typecheck, lint and production build pass. An initial test assertion compared raw desktop gaps against mobile bounds and failed four desktop cases; the assertion now normalizes by canvas width. A Firefox locale test also needed to wait for every visible lazy tile's final loaded state instead of calling `decode()` during a replaced request; its stronger final assertion passed 4/4 affected browser profiles and is tracked under CHG-0050. The previous screenshots and measurements below document the rejected candidate and must not be used as current approval.

## Superseded 28-source-px candidate

Production build at `http://127.0.0.1:3020`, captured on 2026-10-03 after waiting for fonts and decoding the icon images. The PNGs are actual WebKit screenshots at DPR 3. `feature-*` and `technology-*` show the two complete affected icon groups; `*-pro-ar` checks RTL. Browser screenshots show the lines and three dividers still present with the new icon shapes. Icon Y coordinates intentionally sit 28 source px above the original render in response to the latest customer correction, so a whole-section pixel diff against the original would count this requested move as a difference.

Typecheck, ESLint and production build passed. One local Chromium Pro sample reported LCP 144 ms and CLS 0 on loopback; it does not establish field speed, INP, or a Lighthouse score. The existing long-artwork performance issue CHG-0048 is separate and remains open.

The assembled-page pass scrolls from top to footer in 17 positions per phone and captures top, feature, technology and footer viewports at DPR 3. The final eight `assembly-*.webp` files were visually inspected after export from real WebKit screenshots. These contextual images are compressed for repository size; the six icon-group captures remain PNG for direct visual comparison.
